# 数据产品运营与归因分析平台

面向数据产品运营、渠道归因、用户行为分析、ROI评估、转化优化与数据应用监控的数据分析工程平台。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## ROI 核算复用规则

ROI 页面（`frontend/src/views/roi/`）在通用列表之上追加了一套核算逻辑，纯前端实现：

- **核算身份**：`关联活动（归一化为大写）+ 投入金额（按分取整）+ 评估周期（闭区间 YYYY-MM-DD~YYYY-MM-DD）`。
  只要这三项不变，报告就是同一个核算身份，共享 ROI 数值。
- **复用与重算**：缓存按「身份 → 输入指纹」存。输入指纹额外包含转化收入、点击量、曝光量和活动结束窗口；
  指纹相同直接复用数值，不同才真实计算，且只影响该身份下这一份输入。同身份其他报告不受牵连。
- **活动结束窗口**：取投放活动结束日期 + 7 个自然日（结算与归因回补窗口）。评估周期早于活动开始、
  或晚于窗口最后一天时，确认会被完整校验拦下。
- **精度**：ROI 保留 4 位小数，CPC / CPM 保留 2 位小数，四舍五入。投入 / 收入按分做整数归一化，
  避免 `1250`、`1250.0`、`1,250` 被当成不同身份。
- **确认状态各自独立**：确认人、确认时间、归档人只写在自己那一行；归档一份不会连带同身份的其他报告。
  已确认 / 已归档报告不参与重算与被覆盖。
- **并发确认**：两处同时确认同一核算身份时，以「先完成完整校验」的批次为准（完成序号判定，不看谁先写库）；
  后到者返回冲突且不写报告，批次面板保留双方完成序号与胜出批次。
- **缓存不可用**：localStorage 不可用、被探测失败或缓存结构损坏时，一律回退到真实计算，绝不返回旧值，
  页面会显式提示「缓存不可用 · 真实计算」。缓存只是加速层，报告上的数值与状态才是事实来源。
- **失败 / 中断恢复**：提交计算会先落一条批次日志并把报告置为「计算中」。失败或页面中途关闭后，
  报告变为「计算中断」，异常原因保留在报告行；重新进入页面会自动恢复现场，也可从批次面板重试。

可复现的入口在 ROI 页面工具条：`并发确认演练`、`同身份批量重算`、`注入一次核算失败`、
`模拟核算中断` + `模拟刷新并恢复`、`模拟缓存不可用`、`重置示例数据`。清空报告后即可看到空态。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`；ROI 的核算编排在 `frontend/src/api/roi-service.ts`，
  纯计算在 `frontend/src/domain/roi.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-product-ops:entries` 这一项，或调用 `resetModule(模块)`。
